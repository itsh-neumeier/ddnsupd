# Docker IPv6 egress

Enabled IPv6 alongside IPv4 on the Compose egress bridge. The QA override
keeps its unused egress bridge internal and IPv4 only. Both Compose configs
validate. Compose recreated the local egress network and restarted the app
and provider engine. The existing PostgreSQL service stayed running and all
services became healthy.

An isolated probe in the app network namespace confirmed a default IPv6
route. AAAA resolution failed for both configured IPv6 echo endpoints.
Direct IPv6 TCP to the tested public endpoint also failed from both the
container and Windows, so automatic public IPv6 discovery remains unverified.
No DDNS update was requested for this diagnostic.

On 2026-11-11 Windows had an IPv6 default gateway and returned HTTP 200 from
both configured IPv6 discovery services. The same probes from the DDNSupd
network namespace returned HTTP 200 and valid global IPv6 addresses. A
read-only query found no local AAAA bindings, so scheduled AAAA reconciliation
was not exercised.
